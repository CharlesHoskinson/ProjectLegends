# Recommendation Review (2026-06)

Adversarial review of all 36 candidate recommendations from the four CI gap analyses ([[Gap Analysis — Modularity (2026-06)]], [[Gap Analysis — Maintainability (2026-06)]], [[Gap Analysis — Test Coverage Intelligence (2026-06)]], [[Gap Analysis — Always Green (2026-06)]]). Each candidate was checked against the repo at branch `ci-audit`: already implemented? fits the Windows (MSVC, no WSL) + Linux dev loop? respects the GPL engine / MIT proxy split? cost stated? Verdicts: `keep`, `keep-modified`, or `drop`. Dropped candidates stay in the table.

Recent history check: no candidate is implemented by recent work — commits since the Sprint 1 merge are wiki/docs only; the last CI-touching commit is `ee8a9e2` (sanitizer/fuzz gate re-arm), which partially satisfies G-1's premise and nothing else.

## Cross-cutting findings from the review

- **No candidate is already implemented**; the only partial overlap is G-1's re-arm half (commit `ee8a9e2`).
- **No candidate violates the GPL/MIT split.** Two actively strengthen it: M-5 (DAG verification on the license edges) and A-7/T-7's verifier wiring. T-7 stays entirely inside the GPL lane.
- **The MSan tension (M-2 vs G-7) is resolved**: retire the leg with a tracked re-entry condition; presets cover surviving cells only.
- **Sequencing constraints surfaced**: A-1/M-2 are blocked on creating an MSVC-compatible preset; A-2 depends on M-1; T-2's selector activates only after lanes are green; G-2 follows G-1; A-4 (timeouts) has zero prerequisites and can land first.
- **Factual corrections fed back to the gap pages' record**: module-dag build jobs are nightly-only (A-2's five-way claim); T-5's "no Full-mode test callers" is false; T-6's stub conversion is moot; T-8's PR-tier soak contradiction is defused by an env gate; G-6's build.cmd divergence is out of repo scope.
