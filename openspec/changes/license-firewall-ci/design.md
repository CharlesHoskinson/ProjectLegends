# Design: license-firewall-ci

## Context

The firewall has three layers designed and none enforced. Layer 1, configure time: `cmake/ModuleManifest.cmake:63-68` declares the license-critical edges (`LEGENDS_DAG_legends_ipc ""`, `LEGENDS_DAG_legends_proxy "legends_ipc"`, `LEGENDS_DAG_legends_engine_host "legends_core;legends_ipc"`), but `legends_verify_all_dags()` checks only `legends_core`/`legends_pal`/`aibox_core` (cmake/ModuleDAG.cmake:191-209) and `legends_detect_cycles()` hard-codes the same three-module list (cmake/ModuleDAG.cmake:124). Layer 2, link artifact: `cmake/VerifyGPLIsolation.cmake` implements a post-build linker-map scan via `scripts/verify_gpl_isolation.py`, but no `include(VerifyGPLIsolation)` exists anywhere, and its missing-Python/missing-script/unknown-compiler paths are `message(WARNING)` + `return()` — fail-open (cmake/VerifyGPLIsolation.cmake:16-26, 37-40). Its test suite, `tests/scripts/test_verify_gpl_isolation.py`, runs in no workflow. Layer 3, per-file licensing: the rewritten root `LICENSE` is a prose overview and spot-checked MIT trees carry SPDX tags, but nothing in CI verifies any of it stays true; the only scan job is vulnerability-only and advisory (.github/workflows/ci.yml:769-794). Platform coverage: `linux-ipc` (.github/workflows/ci.yml:95-127) is the sole job at any tier setting `LEGENDS_USE_IPC=ON`; its "Verify IPC executables exist" step is an existence check where an isolation check should be; `legends_proxy` and `legends_engine_host` are never compiled on Windows or macOS in CI (audit-wiki/wiki/maps/CI Gate Coverage Map.md, "Platform gap in the IPC stack"). Binding modifications from the adversarial review: Recommendation Review rows M-5 (highest value-to-risk; the one candidate directly enforcing the license boundary) and the verifier halves of A-7/T-7 (verifier must fail closed when prerequisites are missing; the verifier's own tests get a runner). Researched practice: audit-wiki/wiki/sources/Vendored & License-Isolated Dependency CI (2026-06).md.

## Goals / Non-Goals

**Goals:**
- An unauthorized link from a MIT target to a GPL target fails configure with the existing FATAL_ERROR mechanism.
- The shell binary built with `LEGENDS_USE_IPC=ON` is scanned for GPL symbols on every IPC CI run, and a missing scanner prerequisite fails the build rather than silently skipping.
- The verifier script is itself tested in CI, so pattern/allowlist edits cannot silently break the gate.
- Per-file SPDX licensing is mechanically enforced repository-wide (REUSE spec 3.3), including the vendored `engine/` tree, without editing upstream files.
- The IPC split builds and verifies on two OSes at the mandatory tier.
- The include-direction residue of the FSF shared-memory question is enforced: no engine-internal header crosses into the MIT trees.

**Non-Goals:**
- Deciding the legal question. Whether the shared-memory framebuffer/audio channels are "complex internal data structures" in the FSF FAQ's sense is flagged for counsel in the source page's conflict callout; CI enforces only mechanically checkable invariants.
- Relicensing anything. `REUSE.toml` annotations record currently documented status; the `-only`-vs-`-or-later` declaration remains the maintainer's (LICENSE, "License policy clarification").
- SBOM generation and per-artifact license manifests (practices 6-7 of the source page) — tag-tier packaging work, separate change.
- Workflow consolidation, presets, path filters, action SHA-pinning — R8/R5/R6/R13 territory; the new jobs follow current ci.yml conventions and get migrated with everything else.
- macOS IPC coverage. Two OSes at the mandatory tier is R7's bar; macOS lanes are nightly/dispatch-only today (.github/workflows/ci.yml:263, 301).

## Decisions

**D1 — DAG extension: verify the declared edges; add a transitive rule for the MIT targets.**
Add `if(TARGET ...)`-guarded `legends_verify_dag()` calls for `legends_ipc`, `legends_proxy`, `legends_engine_host` to `legends_verify_all_dags()` (matching the existing guard style, cmake/ModuleDAG.cmake:196-206) and add the three names to `legends_detect_cycles()`'s module list. The guards matter because `legends_proxy`/`legends_engine_host` exist only under `LEGENDS_USE_IPC=ON` (CMakeLists.txt:373, 405), so the boundary check is exercised only by IPC-configured builds — which is why D6's second IPC cell also strengthens this layer. Additionally, `legends_verify_dag()` reads only direct `LINK_LIBRARIES` and its `EXTERNAL_PATTERNS` whitelist is generous (cmake/ModuleDAG.cmake:52-61); for `legends_ipc` and `legends_proxy` specifically, add a stricter check that walks `INTERFACE_LINK_LIBRARIES` transitively and FATAL_ERRORs on any `aibox_core`, `legends_core`, or engine-prefixed target. Alternative rejected: relying on the direct-link check alone — a GPL dependency laundered through an intermediate target's interface would pass it.

**D2 — Fail-closed verification is an explicit option CI always sets.**
Add `option(LEGENDS_REQUIRE_GPL_VERIFICATION "Fail configure if GPL isolation verification cannot run" OFF)`. When ON, the three degrade paths in `VerifyGPLIsolation.cmake` (no Python3, missing script, unknown compiler) become `FATAL_ERROR`. Both IPC CI jobs configure with `-DLEGENDS_REQUIRE_GPL_VERIFICATION=ON`. Default OFF preserves local configurability on Python-less machines. Rationale: Recommendation Review M-5/A-7 binding — a gate that silently vanishes on a misconfigured runner is the exact failure class this audit exists to end. Alternative rejected: making fail-closed unconditional — it would hard-fail local non-CI workflows for a check those builds may not need, inviting the gate's removal.

**D3 — Scan target: the shell binary; the proxy is covered transitively.**
`VerifyGPLIsolation.cmake` instruments `project_legends` (`/MAP` on MSVC, `-Wl,-Map` on GCC/Clang, cmake/VerifyGPLIsolation.cmake:29-40). Keep that target: `legends_proxy` is a static library with no link step and therefore no map; in IPC mode the shell links the proxy, so every object the proxy contributes appears in the shell's map. The invariant scanned is the FSF's same-executable criterion (modules in one executable are "definitely combined in one program", per the FSF FAQ as quoted in the source page) applied to the one MIT-side executable the build produces. A standalone proxy-consumer link test (a minimal MIT executable linking only `legends_proxy`) is recorded as an open question, not blocking.

**D4 — The verifier's tests run in the job the verifier gates.**
Add a `python3 tests/scripts/test_verify_gpl_isolation.py` step to `linux-ipc` before the build (the file is self-running with its own fixtures and exit code; no pytest dependency). Placement rationale: the test proves the gate can fail (known-bad MSVC and GCC map fixtures must exit nonzero) at the same tier where the gate's verdict is consumed — a green isolation scan is meaningless if the scanner regressed to pass-everything. Alternative rejected: sprint2-checks.yml — it is path-filtered (`.github/workflows/sprint2-checks.yml:3-27`) and structurally ineligible to be a required check; the firewall belongs on the unfiltered workflow.

**D5 — REUSE: root `REUSE.toml` with bulk engine annotations; turnkey action job.**
Adopt REUSE spec 3.3: `LICENSES/` holds the text of every SPDX identifier in use; a root `REUSE.toml` carries `[[annotations]]` for the vendored `engine/` tree with `precedence = "closest"`, so upstream in-file headers win and the TOML only fills gaps — the spec names exactly this vendored-directory use case, and it avoids touching upstream files (which would bloat every future vendor-drop diff). Project-owned files that lack tags (e.g. `include/legends/legends_embed.h` carries no SPDX line today) get either an SPDX tag matching the LICENSE table's documented status or a `REUSE.toml` annotation; no licensing decision is created, only recorded. The job is `fsfe/reuse-action` in ci.yml on push and pull request, unfiltered, so it is requirable under R2/R6. This subsumes the five-line-grep SPDX lint (source page, practice 3) — one mechanism, not two. Alternative rejected: a bespoke grep gate — cheaper to land but it would not catch missing-license-file, unused-license-file, or new-untagged-file classes that `reuse lint` covers.

**D6 — Windows IPC cell mirrors `windows`, adds the IPC flag, and runs the MSVC verifier path.**
New `windows-ipc` job (name: `Windows IPC (MSVC)`) in ci.yml: the `windows` job's configure/build/test shape (.github/workflows/ci.yml:189-207) plus `-DLEGENDS_USE_IPC=ON -DLEGENDS_REQUIRE_GPL_VERIFICATION=ON`. This compiles the Windows-only IPC platform sources for the first time in CI (`shared_memory_win.cpp`, `control_channel_win.cpp`, `engine_spawner_win.cpp`, CMakeLists.txt:338-343), exercises `verify_gpl_isolation.py`'s MSVC `/MAP` parsing in anger, and runs the IPC-gated ctest set on a second OS. Bring-up is rehearsed by `workflow_dispatch` before the job joins any required set: this configuration has never been built in CI and may surface real defects — surfacing them is the job's purpose, but a never-green job must not be born required (the 2026-06-08 demotion lesson).

**D7 — Counsel boundary: enforce the residue, record the question.**
The FSF FAQ position on shared memory ("pretty much equivalent to dynamic linking", per the source page's quotation) versus the design's framebuffer/audio shared-memory channels is a legal question the source page explicitly routes to counsel, not to CI. What CI enforces is the checkable residue: files under `src/legends_ipc/`, `include/legends_ipc/`, and `src/legends_proxy/` must not include engine-internal headers (`engine/include/**`, `engine/src/**`, `dosbox/`/`aibox/` prefixed includes) or private `src/legends/**` headers — so the shared-memory structs stay defined entirely in the MIT layer and no engine-internal type can appear in `include/legends_ipc/`. Implementation home: extend `scripts/check_includes.py` (already manifest-driven and CI-run) rather than a new script. Observed fact recorded for counsel's file, not failed by CI: the MIT trees include `<legends/legends_embed.h>` (src/legends_proxy/proxy_api.cpp:6, include/legends_ipc/messages.h:14), the stable C ABI surface, which is untagged today and sits in a tree the LICENSE table describes as GPL-tagged. The rule deliberately scopes to engine-internal and private headers so it is green on the current tree while still catching the drift class that matters (an engine struct leaking into the wire format).

## Risks / Trade-offs

- [The transitive-link walk (D1) over-fires on generator expressions or imported targets] → Reuse the existing `EXTERNAL_PATTERNS` classification for leaf nodes; the strict rule rejects only named internal GPL targets. Seeded-violation tests in bring-up prove both directions.
- [`GPL_PATTERNS` prefixes like `IO_`, `DOS_`, `TIMER_` (scripts/verify_gpl_isolation.py:17-41) false-positive on MIT or CRT symbols in real MSVC maps] → The allowlist (scripts/verify_gpl_isolation.py:44-58) absorbs known false positives; every pattern change is gated by the now-CI-run test suite; first Windows runs happen on dispatch (D6) where a false positive costs a triage, not a blocked merge.
- [`reuse lint` over the ~1M-line engine is slow or noisy on first run] → The tool is a linter, not a scanner — cost is file enumeration; noise is burned down once during bring-up via annotations, after which only new files can fail. Vendor drops re-run the same lint, which is the point.
- [Bulk engine annotations misdescribe an oddly-licensed upstream file] → `precedence = "closest"` means any in-file header wins over the annotation; the annotation states only the directory-level default already documented in `NOTICE`/`COPYING`. The annotation records, it does not conclude.
- [The `windows-ipc` configuration has never compiled and bring-up stalls] → Dispatch-rehearsal-first (D6); defects found are filed and fixed or the job ships `workflow_dispatch`-gated with a tracked promotion issue — never silently dropped (lane-demotion rule from ci-stabilize-mandatory-lanes applies from birth).
- [New mandatory jobs widen the required-check set out from under the R2 ruleset] → Explicit handoff in the proposal's Impact: the ruleset change adds the new exact names in the same change that makes them required; this change's jobs run unconditionally (no path filter) so they are requirable as-is.
- [Fail-open remains the local default (D2)] → Acceptable: the spec requirement binds CI behavior; local builds without Python lose a check they cannot run, and both IPC CI jobs set the option, so no gated path is fail-open.

## Migration Plan

1. DAG extension (D1) + seeded-violation proof: a scratch branch adds `legends_core` to `legends_proxy`'s links and configure must FATAL_ERROR; clean tree must configure green with the three new "verified" lines.
2. Verifier wiring (D2-D4): `include(VerifyGPLIsolation)` in the IPC branch, fail-closed option, `linux-ipc` gains the test-runner step and `-DLEGENDS_REQUIRE_GPL_VERIFICATION=ON`; dispatch run shows the post-build scan PASS line and the verifier tests green.
3. REUSE bring-up (D5): `LICENSES/`, `REUSE.toml`, tag-or-annotate sweep until `reuse lint` is green locally; land the job in the same PR as the green state.
4. Windows IPC cell (D6): dispatch rehearsals until green, then promote to the PR+push tier; include-direction check (D7) lands with whichever of steps 2-4 finishes first.
5. Handoff: notify the R2 ruleset change of the final job names.

Rollback for any step is a revert of that step's PR; no step weakens an existing gate, so partial landing leaves CI no worse than found.

## Open Questions

- Standalone proxy-consumer link test (a minimal executable linking only `legends_proxy`, map-scanned like the shell) — worth a target, or is the shell scan sufficient until a real external consumer exists? Default: defer; record in the verifier-coverage issue.
- Where the engine settles between `GPL-2.0-only` and `GPL-2.0-or-later` for the `LICENSES/` file set — maintainer's call (LICENSE defers it); bring-up uses the identifiers the source tags already state and includes both texts if both appear.
- Whether the include-direction rule should also forbid `include/legends/**` (beyond private `src/legends/**`) in the MIT trees once counsel rules on the C-ABI-header question — spec scopes to engine-internal/private headers now; widening is a one-line pattern change later.
