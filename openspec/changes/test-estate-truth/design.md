# Design: test-estate-truth

## Context

Seven CTest-visible executables carry suite-granularity labels only (`unit`, `integration`, `ipc`, `abi`, `toolchain`, `determinism`; audit-wiki/wiki/entities/Project Legends Test Suite.md, label table). All ~4,600 unit tests share the single label `unit`, so `ctest -L` cannot express "only IPC unit tests"; two workflows instead reach into the binary with gtest string filters (`sprint2-checks.yml:111`, `pal-ci.yml:162`), bypassing CTest's fixture and label machinery. The `soak` label is referenced in three exclusions (`CMakeLists.txt:1031, 1045`; `.github/workflows/ci.yml:905`) and one selection (`test-soak`, `CMakeLists.txt:1037-1041`) but applied to nothing — the comment at `CMakeLists.txt:1021-1028` defers to a `cmake/SoakTestLabels.cmake` that does not exist, so `-L soak` selects zero tests and every `--label-exclude soak` excludes nothing. The determinism suite has a label and a `test-determinism` target (`engine/tests/determinism/CMakeLists.txt:33-45`) selected by no workflow; the hash CI would compare is pinned to `HashMode::Fast` at the library entry point (`dosbox::get_state_hash(g_context.get(), dosbox::HashMode::Fast)`, `engine/src/misc/dosbox_library.cpp:685`), while `Full` covers conventional memory only (`engine/src/misc/state_hash.cpp:296-305`) and already has test callers (`engine/tests/unit/test_dosbox_state_hash.cpp:104-136`). Three integration sources compile into no target: `test_dual_ffi.cpp` (viable), `test_context_synchronization.cpp` and `test_error_propagation.cpp` (bit-rotted: nonexistent `legends_init(handle)`; 3 args to the 4-parameter `legends_get_last_error`, `include/legends/legends_embed.h:644-649`). Eight of 33 registered integration files are one-line `GTEST_SKIP()` stubs reporting green. Soak endurance tests are env-gated (`GTEST_SKIP` unless `LEGENDS_SOAK_ENABLED=1` or `LEGENDS_SOAK_SHORT=1`, `tests/integration/test_soak_endurance.cpp:76-83`) and the `test-soak` per-test timeout of 46800 s exceeds the 6-hour GitHub-hosted runner cap.

Binding modifications from the adversarial review (audit-wiki/wiki/syntheses/Recommendation Review (2026-06).md rows M-6, T-1, T-5, T-6, T-7, T-8): preserve `--gtest_repeat=3` semantics in the asan-lifecycle step (`pal-ci.yml:213-214`); every new `ctest -L` step asserts nonzero selection; the "Full has no test callers" claim is wrong — the switch targets the library entry point and harness, not the hash internals; the stub-file rewrite step is moot (they are already one-line skips) — keep the visibility half; rewrite-or-delete for the two rotted orphans, removal recorded; nightly soak must export the env gate and bound durations.

## Goals / Non-Goals

**Goals:**
- Every label that appears in a `-L`/`--label-exclude` expression is applied to at least one test, enforced mechanically.
- Module-level selection inside the monolithic suites via labels, replacing raw gtest string filters in workflows.
- A PR-tier determinism job that can actually fail: real label selection, a canary, and a hash mode the caller chooses.
- No test source on disk that is silently compiled into nothing.
- Skip-stubs visible in every CTest report rather than disguised as green tests.
- Soak runs nightly for real: label applied, env gate exported, durations inside the runner cap.

**Non-Goals:**
- Splitting `legends_unit_tests` into per-module binaries — labels select within the binary; the split (which also saves compile/link time) is the named follow-on (Recommendation Review row M-6; audit-wiki/wiki/sources/Test Impact Analysis & Selection (2026-06).md, monolithic-binary section).
- Extending `Full` hash coverage to VGA registers, VRAM, and device state — engine serialization work owned by `phase-b-serialization` (Recommendation Review row T-5).
- DAG-driven test selection (changed-path → reverse closure) — deferred until the lanes hold green (CI-THESIS.md, T-2 deferral).
- Gating-tier or required-check policy — owned by `ci-stabilize-mandatory-lanes` / `master-ruleset-required-checks`.
- Deleting or weakening any assertion (R11 territory; the rule "never delete an assertion to make CI pass" binds here too).

## Decisions

**D1 — Module labels attach at the discovery call, grouped by source prefix; regexes are anchored.**
`gtest_discover_tests` registers tests at CTest time, so configure-time `set_tests_properties` cannot relabel them (existing comment, `CMakeLists.txt:1023-1028`). Labels therefore ride the discovery calls: the unit suite gains per-module labels (`mod_ipc`, `mod_pal`, `mod_core`, …) aligned with the module prefixes in `cmake/ModuleManifest.cmake`, attached via multiple discovery calls with `TEST_FILTER` over the existing flat `test_<area>` naming, or a discovery-time properties hook — whichever the CMake version in CI supports without races. Every workflow `-L` expression is anchored (`-L '^unit$'`): CTest label matching is regex-substring, and unanchored short labels over-match (audit-wiki/wiki/sources/Test Impact Analysis & Selection (2026-06).md, practice 1). Alternative rejected: per-test `RecordProperty`/naming conventions parsed by scripts — labels are the native CTest selector and compose with `FIXTURES_REQUIRED` for free (same source, practice 6).

**D2 — Nonzero-selection guard wraps every `-L` step.**
A small helper (script step or CMake function used by the custom targets) runs `ctest -N -L <expr>`, fails if the selected count is zero, then runs the real invocation. Applied to all existing custom targets (`legends-test-unit`, `test-integration`, `test-abi`, `test-toolchain`, `test-determinism`, `test-soak`) and every workflow `ctest -L` step this change adds or converts. Rationale: the estate already shipped one vacuous label; a label that selects nothing must be a hard failure, not a quiet green (Recommendation Review row T-1). Alternative rejected: relying on `ctest --no-tests=error` alone — it exists and is used where available, but the guard also catches the "label selects only stubs" case when paired with D5's stub label, and gives one uniform mechanism across CMake versions.

**D3 — Workflow gtest string filters become label selections; asan-lifecycle keeps its repeat semantics.**
`sprint2-checks.yml:111` (`--gtest_filter="MultiInstance*:Sprint2*:GslContract*:ContractGates*"`) and `pal-ci.yml:162` (`--gtest_filter="ContractGate*"`) become `ctest -L` selections over labels applied at discovery (e.g. `sprint2`, `contract_gate`), restoring CTest's fixture/timeout machinery. The asan-lifecycle step (`pal-ci.yml:213-214`) currently runs `ContractGate_Lifecycle*` with `--gtest_repeat=3`; CTest has no per-test repeat passthrough that preserves "same process, three iterations" semantics, so that step keeps direct binary invocation with `--gtest_repeat=3` (binding, Recommendation Review row M-6) — but gains the guard's sibling check that the filter matches a nonzero test count (`--gtest_list_tests` piped through the filter). Alternative rejected: `ctest --repeat until-pass:3` — different semantics (re-runs the test process; the lifecycle ASan check wants same-process re-entry to catch leaks across iterations).

**D4 — Determinism: a PR-tier job runs `-L '^determinism$'`; a canary proves the oracle can fail; the entry point stops hardcoding `Fast`.**
The job builds the engine tests and runs the existing `determinism` label under the D2 guard — the label and target already exist (`engine/tests/determinism/CMakeLists.txt:33-45`); no workflow runs them, which is the cheap half of T-5. The canary is a test that perturbs hashed state between two hash calls and asserts the hashes differ — if the oracle cannot distinguish a mutated machine, the canary fails, converting "oracle too weak" from a wiki finding into a red check. The entry point change: `dosbox_lib_get_state_hash` (`engine/src/misc/dosbox_library.cpp:685`) takes the mode from its caller (new parameter or library-config flag, default preserving current ABI behavior) instead of pinning `HashMode::Fast`; the determinism harness selects `Full`. `Full` already has test callers (`engine/tests/unit/test_dosbox_state_hash.cpp:104-136`), so this is plumbing, not new oracle code. What `Full` covers stays as-is — conventional memory plus CPU/context state; widening it is Phase B engine work (binding scope cut, Recommendation Review row T-5). Alternative rejected: switching the default to `Full` for all callers — penalizes the interactive save/load path that wants `Fast`, and couples this change to ABI review.

**D5 — Skip-stubs get a `stub` label and a tracked issue; the orphan trio is compiled or consciously deleted.**
The 8 skip-stub integration files gain `LABELS "integration;stub"` at discovery plus a tracked-issue reference in the `GTEST_SKIP()` message, so `ctest --print-labels` and every report shows the debt; gates may exclude `-LE '^stub$'` but the label is always visible (Recommendation Review row T-6 — the rewrite step is moot, visibility is kept). `test_dual_ffi.cpp` joins `legends_integration_tests` (it is viable against the current API). `test_context_synchronization.cpp` and `test_error_propagation.cpp` are rewritten against the current embed API (`legends_create`/4-arg `legends_get_last_error`) if their scenarios — context sync and error propagation across the FFI boundary — are judged worth keeping, else deleted; either way the disposition is recorded in the commit message and the tasks checklist (Recommendation Review row T-7: "compile-or-consciously-delete"). Alternative rejected: committing them with `DISABLED_` prefixes — that preserves dead code without a compile guarantee; orphaned sources that do not compile are the problem being fixed.

**D6 — Soak: label applied in-tree, nightly job exports the gate, durations bounded.**
The dead `SoakTestLabels.cmake` indirection is replaced by direct label application at discovery: the soak endurance tests get `LABELS "integration;soak"` (post-discovery property attachment by test-name prefix, the mechanism the comment at `CMakeLists.txt:1021-1028` described but never shipped). With the label real, the existing exclusions (`test-integration`, `legends-test-all`, `ci.yml:905`) start excluding something and `test-soak` starts selecting something — both now under the D2 guard. A nightly job (cron tier) runs `-L '^soak$'` with `LEGENDS_SOAK_ENABLED=1` exported — without it every soak test is a `GTEST_SKIP` and the job is theater (`tests/integration/test_soak_endurance.cpp:76-83`, binding per Recommendation Review row T-8). Durations: `LEGENDS_SOAK_DURATION_HOURS` set so total job time, plus build, sits inside the 6-hour runner cap; the `test-soak` ctest `--timeout 46800` (`CMakeLists.txt:1038`) drops to match. Local long-soak (multi-hour) remains available by overriding the env var off-CI. Alternative rejected: `LEGENDS_SOAK_SHORT=1` in the nightly — it clamps to 10 s per test, which is smoke, not soak; the nightly uses real durations bounded by the env knob that already exists.

## Risks / Trade-offs

- [Discovery-time label attachment differs across CMake versions; a wrong mechanism silently applies no labels] → The D2 guard is the backstop: a label that matches nothing fails the step the first time it runs, in the same PR that introduces it.
- [Anchored-regex conversion breaks an existing selection that depended on substring matching] → Audit of every `-L`/`-LE` expression in workflows and custom targets is part of the conversion; the guard catches the empty-selection direction, and the full nightly suite catches the over-exclusion direction.
- [The determinism canary is itself flaky (perturbation not hash-visible on some platform)] → The canary perturbs state that `Full` provably hashes today (conventional memory, `engine/src/misc/state_hash.cpp:296-305`); it asserts inequality of hashes over a mutation, not equality over reruns, so scheduler nondeterminism cannot flake it.
- [Switching the harness to `Full` slows the determinism suite past its TIMEOUT 120] → `Full` hashes conventional memory linearly; if the timeout trips, the suite's TIMEOUT property is raised in the same commit — never by reverting to `Fast`, which re-blinds the oracle.
- [Rewriting the rotted orphans produces tests that pass vacuously against the new API] → Rewrites must assert the original scenario intent (cross-context synchronization; error-code propagation fidelity), reviewed against `legends_embed.h` semantics, or the files are deleted — a recorded deletion is preferred over a hollow pass (Recommendation Review row T-7).
- [Nightly soak red is low-urgency and rots] → The job is cron-tier, not PR-gating, by design; its failures feed the flake/triage ledger under R11 (`flake-quarantine-burnin`) rather than blocking merges.
- [Bounding soak durations weakens the endurance claim] → Trade accepted: a 6-hour-bounded nightly that runs beats a 13-hour configuration that cannot ever complete on hosted runners; longer soaks remain a self-hosted/local option via the same env knobs.

## Migration Plan

1. Land module labels + anchored regexes + the D2 guard on existing custom targets (no workflow behavior change yet; guard proves labels are live).
2. Convert `sprint2-checks.yml:111` and `pal-ci.yml:162` to `ctest -L`; asan-lifecycle keeps `--gtest_repeat=3` with the filter-count check (D3).
3. Soak label application + `test-soak` timeout bound + nightly soak job with `LEGENDS_SOAK_ENABLED=1` and bounded `LEGENDS_SOAK_DURATION_HOURS` (D6).
4. `stub` labels on the 8 skip-stubs with tracked issues; `test_dual_ffi.cpp` into the integration target; rewrite-or-delete the two rotted orphans with the disposition recorded (D5).
5. Hash-mode switch at `dosbox_lib_get_state_hash` + canary test + PR-tier determinism job under the guard (D4). Lands last because it adds a new PR-tier signal; required-check membership is decided under `master-ruleset-required-checks`.

Rollback: each step is independently revertible; the guard steps fail closed (a reverted label turns its selector red rather than silently green).

## Open Questions

- Which discovery-time mechanism for post-discovery property attachment (per-prefix `gtest_discover_tests` calls with `TEST_FILTER` vs a CTest hook script) the CI CMake version supports cleanly — resolved by the first guard run in step 1.
- Whether the hash-mode switch is a new exported parameter or a library-config flag — constrained by ABI stability rules under `abi-parity-negative-gates`; decided at implementation with the default preserving current behavior.
- Final disposition (rewrite vs delete) per rotted orphan — decided against scenario value during step 4; both outcomes satisfy the spec provided the record exists.
